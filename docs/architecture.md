# Current architecture and evidence boundaries

WorldSpeak separates perception, user intent, deterministic rendering and speech authorization. Next.js App Router/React/strict TypeScript serve the responsive UI and authenticated routes; Supabase supplies Auth, PostgreSQL and private transient Storage. The essential guest board remains usable without Auth and can be prepared offline. English/Tamil wording remains review-pending until independent native review.

## Components and contracts

- `apps/web`: explicit capture/upload review, per-upload consent, bounded job polling, validated object overlays, separate object/catalog/intent confirmation, exact preview and tab-local composer handoff. Guest fixtures never upload. Raster masks join detections by stable SAM objectId; malformed/ambiguous mask batches fail closed. Binary textures use bounded source-resolution canvases inside the fitted image layer, with accessible existing region/list buttons and no fabricated contours.
- `packages/contracts`: strict request/status/result/provenance schemas. Historical/scene detections remain compatible without objectId; segmented results require matching IDs in the frontend adapter. A job response must match its requested operation/model. No JSON-string response fallback exists.
- `packages/communication` and `packages/catalog`: pure typed intent/rendering, structural negation and exact user text. Provider labels do not establish desire or reviewed catalog identity. Only a fresh Speak gesture authorizes the exact composition revision/hash; detection, replay, restore and language changes never speak automatically.
- `apps/worker` / `packages/inference`: server-only Meta Responses construction/parsing, SHA-verified normalized still input, durable claims/leases and dispatch fencing, integer micro-USD reservations, uncertain outcomes without automatic retries, typed Postgres.js JSONB writes, and a separate cleanup-only command. SAM raster masks are retained separately from polygons; real video model validation remains open.
- PostgreSQL/Storage: owner-derived Auth checks, owner-only RLS, immutable ownership and composite owner/parent keys. Private media expires and is revoked/queued for deletion. Cleanup outbox survives Auth deletion, uses lease tokens and bounded retries; a database acknowledgement is not independent physical Storage deletion evidence. Worker login has only restricted inherited capabilities, verified TLS and no table/authorization privileges.
